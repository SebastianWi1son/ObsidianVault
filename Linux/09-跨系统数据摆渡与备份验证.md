# 跨系统数据摆渡与备份验证

场景：重装系统前，把资料转移到 Windows 的 NTFS 分区。

---

## 一、挂载 NTFS

```bash
lsblk -o NAME,SIZE,FSTYPE,LABEL,UUID          # 先看清楚哪个分区是哪个
sudo mkdir -p /mnt/win-data
sudo mount -t ntfs3 /dev/nvme0n1p5 /mnt/win-data
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS /mnt/win-data   # ★ 挂上后必须确认选项
```

**两个驱动**：
| 驱动 | 来源 | 说明 |
|---|---|---|
| `ntfs3` | 内核内置（5.15+） | 快，推荐，`-t ntfs3` |
| `ntfs-3g` | 用户态 FUSE | 老方案，兼容性好但慢 |

**常见失败：挂上了却是只读**
```
falling back to read-only / volume is dirty
```
原因是 **Windows 的「快速启动」** —— 它关机时其实是休眠，NTFS 日志没提交完，
Linux 为了不破坏数据主动降级为只读。
正解：在 Windows 里关掉「快速启动」后完整重启一次。
急救：`sudo ntfsfix -d /dev/nvmeXnXpX`（有风险，非首选）。

## 二、NTFS 没有 Unix 权限位

挂上后 `findmnt` 会看到 `uid=0,gid=0` —— 整个分区被伪造成 root 所有，
普通用户写不进去。因为 **NTFS 根本不存 Unix 的 uid/gid/mode**，
驱动只能给整个挂载点编一个统一的属主。

```bash
sudo mount -o remount,uid=$(id -u),gid=$(id -g) /mnt/win-data
```

**推论：NTFS 不适合做 Linux 的系统级备份介质**，因为它丢失：
- 文件权限与属主
- **符号链接**（rsync 会报错或降级成实体文件）
- 硬链接、特殊文件

它适合**摆渡资料**（文档、源码、笔记）。要完整保留权限就得用 tar 打包
（把元数据编码进包里），或者直接用 ext4 的外置盘。

## 三、验证：`du` ≠ `stat`

这次踩到的坑：备份完用 `du -h` 检查，两个文件显示 `0`，以为丢了。

| 命令 | 回答的问题 |
|---|---|
| `du` | **占了多少磁盘块** |
| `stat -c %s` / `ls -l` | **文件有多少字节** |

NTFS 驱动不汇报块占用 → `du` 全报 0。两者在**稀疏文件、压缩文件系统、
tmpfs** 上同样会严重不一致。

> **验证文件完整性一律用 `stat`，`du` 只用来看空间占用。**

## 四、备份的验证套路

**没验证过的备份不算备份。** 三步：

```bash
# 1. 结构对不对
find /备份路径 -maxdepth 2 | sort

# 2. 内容逐字节比对（最硬的证据）
diff -rq ~/源目录 /备份路径/源目录 && echo "完全一致"

# 3. 数量对不对
find ~/ -type f | wc -l ; find /备份路径 -type f | wc -l
```

`diff -rq` 的 `-r` 递归、`-q` 只报"不同/相同"不打印差异内容 ——
比对大目录时必须加 `-q`，否则会把二进制文件差异全喷出来。

## 五、分区布局决定重装的代价

本机布局（这是当初分对了的红利）：
```
nvme0n1p1   100M  vfat  /boot/efi   ← Windows 和 Linux 共用，重装时【绝不能格式化】
nvme0n1p3/5/6      ntfs             ← Windows，别碰
nvme0n1p7   143G  ext4  /           ← 系统，重装时格式化的就是它
nvme0n1p8   238G  ext4  /home       ← 【独立分区】重装挂上去不勾 Reformat，数据一个字节不动
nvme0n1p9  18.5G  swap              ← 可复用
```

**`/home` 独立成分区，是"换发行版"从大手术变成小手术的唯一原因。**
新装任何发行版时在手动分区里把它挂成 `/home` 且不勾 Reformat 即可。

代价是 `/` 的空间是固定的，装多了会满；好处是重装、换发行版、系统崩溃
都不影响个人数据。对于要折腾环境的开发机，这个交换划算。

> EFI 分区（p1）是 Windows 和 Linux **共用**的引导分区。
> 装 Linux 时把它挂成 `/boot/efi` 但**不要格式化** —— 格了 Windows 引导项会一起消失。

## 六、附带说明：`--info=progress2` 的输出

`rsync --info=progress2` 用回车符 `\r` 原地刷新进度条。
在正常终端里看着很好，但**复制粘贴出来会变成几百行重复**（因为 `\r` 没被解析）。
要把日志贴给别人看，用 `--info=stats2` 或直接不加进度参数。
