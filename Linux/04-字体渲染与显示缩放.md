# 字体渲染与显示缩放

## 三层模型

遇到「字糊」先定位在哪一层。大多数人一上来就去折腾第 1 层（改 hinting、装字体），**方向通常是错的**。

| 层 | 管什么 | 配置在哪 |
|---|---|---|
| **1. fontconfig + FreeType** | 选哪个字体文件、抗锯齿、hinting、亚像素渲染 | `/etc/fonts/conf.d/`、`~/.config/fontconfig/` |
| **2. 工具包**（GTK/Qt/Electron） | 用什么字体字号、排版、**决定按多少像素渲染字形** | gsettings、各应用自己的配置 |
| **3. 合成器缩放** | Wayland 分数缩放 / 位图放大 | GNOME 显示设置 |

## 一个「好」字的完整旅程

```
┌──────────────────────────────────────────────────────────┐
│ 第 2 层：工具包                                            │
│  "显示「好」，字号 11pt，合成器说我的缩放比是 S"            │
│  "所以我需要 11 × S × (DPI/72) 像素高的字形"    ← 关键决策   │
└─────────────────────┬────────────────────────────────────┘
                      │ 「给我 N 像素大的『好』」
                      ↓
┌──────────────────────────────────────────────────────────┐
│ 第 1 层：fontconfig + FreeType                            │
│  fontconfig: 「好」→ 匹配到 Noto Sans CJK SC 字体文件      │
│  FreeType:   取出矢量轮廓 → 按 N 像素光栅化成位图          │
│     ├─ hinting=slight  微调笔画对齐像素网格                │
│     └─ antialias=rgba  利用 LCD 子像素提高水平精度         │
└─────────────────────┬────────────────────────────────────┘
                      │ 像素位图
                      ↓
┌──────────────────────────────────────────────────────────┐
│ 第 2 层（续）：排版定位，画进自己的窗口 buffer              │
└─────────────────────┬────────────────────────────────────┘
                      │ buffer 交给合成器
                      ↓
┌──────────────────────────────────────────────────────────┐
│ 第 3 层：合成器 mutter                                     │
│  收齐所有窗口 buffer → 拼成 1920×1200 → GPU → 屏幕         │
│  ⚠️ buffer 尺寸 ≠ 该占的屏幕区域 → 只能位图拉伸            │
└──────────────────────────────────────────────────────────┘
```

**最关键的一点**：字形渲染成多大，是**第 2 层决定、第 1 层执行**的。第 1 层再优秀，第 2 层要求「按 1 倍渲染」，出来的字形就只有 1 倍细节。

## 分数缩放为什么会糊

Wayland 下应用自己负责画（见 [[03-Wayland与X11架构]]）。125% 缩放时 mutter 对每个应用说「你的缩放比是 1.25」：

```
懂分数缩放的应用（实现了 wp_fractional_scale_v1）
   → 按 1.25 倍要字形 → 高细节 → buffer 尺寸正好 → 直接贴  ✅ 锐利

不懂的应用
   → 「我不认识 1.25，按 1 倍吧」→ buffer 只有 1536×960
   → 却要铺满 1920×1200 → 合成器位图拉伸                   ❌ 糊
```

**位图拉伸不可逆**：应用按 1 倍画的时候，细节根本没被画出来。合成器手里只有小图，放大只能插值猜像素。

> 类比：应用按 1x 渲染 = 拍了张 1536×960 的照片，拉伸 = 把照片放大。
> 应用按 1.25x 渲染 = 直接拍了张 1920×1200 的照片。

**XWayland 应用全部属于「不懂」那一类**，缩放≠100% 时必糊。

## 解决方案：放大字体 ≠ 放大画面

```
分数缩放 1.25：  小字形 ──位图拉伸──> 大而糊
文字缩放 1.5：   直接渲染大字形 ───> 大而清晰
```

**`text-scaling-factor` 完全不碰第 3 层**。它直接对第 2 层说「原来 11pt，现在用 16.5pt」，第 2 层于是向第 1 层要一个更大的字形，**从源头就是大的、细节完整的**，全程没有位图拉伸。

缩放比 = 1.0 时，「按 1 倍渲染」对所有应用都成了正确答案，不懂分数缩放的也蒙对了。

### 本机方案（T14s Gen3，14" 1920×1200 ≈ 162 DPI）

1. Settings → Displays → Scale = **100%**
2. ```bash
   gsettings set org.gnome.desktop.interface text-scaling-factor 1.5
   ```
   可实时调，试 `1.15` / `1.25` / `1.5`。还原：`gsettings reset ...`

**代价**：只放大文字，图标/按钮/标题栏保持原大小。取舍：
- **100% + 字体放大** → 全局锐利，图标偏小 ← **当前采用**
- **保持 125%** → 图标舒服，但 fcitx5 候选窗和所有 XWayland 应用会糊，且**无法逐个修**（上游代码没实现协议，改配置没用）

## 诊断命令

```bash
xrandr | grep ' connected'          # 逻辑分辨率 + 物理尺寸
                                    # 逻辑 ≠ 面板分辨率 → 正在分数缩放
gsettings get org.gnome.mutter experimental-features
                                    # ['scale-monitor-framebuffer'] = 分数缩放已开
gsettings get org.gnome.desktop.interface text-scaling-factor
xlsclients -l                       # 谁在 XWayland 上（这些必糊）
```

**实测例子**：面板 1920×1200，但 `xrandr` 报 `1536x960` → 1920÷1536 = **1.25，正在跑 125% 缩放**。

## 健康的第 1 层长什么样（供对照）

```
font-antialiasing  'rgba'      # 亚像素抗锯齿
font-hinting       'slight'    # 现代字体的推荐值
```
Ubuntu 默认就是这个组合，一般不需要动。中文字体装 `fonts-noto-cjk` 即可。
