# 对话总结：回调设计 — 函数指针 + ctx（2026-08-23）

> 纯事实总结。背景：cyclotron foc 库 D5 决策讲解（hal.hpp 设计）；legacy `lib/foc/foc.h` 无参回调 vs cyclotron `void* ctx` 通道
> 关联：`foc/docs/FOC_MATH_SPEC.md`、`docs/FOC_GUIDE.md`（D5 记录表）

## 一、核心结论

**回调设计的核心 = 能不能带参数（通道）**。函数指针本身是纯代码、无状态；没有参数通道，回调就只能摸全局变量。

**函数指针 + ctx = C 语言手搓闭包**：函数指针是"代码"，ctx 是"捕获的环境"。回调被调用时，ctx 告诉它"我是谁、我的状态在哪"。

## 二、演进链

| 形态 | 通道 | 问题 |
|---|---|---|
| legacy | 无（`void` 参） | 必须全局变量；每实例手写适配器样板（双轴 = 2×5 个复制函数） |
| wheel（lunokhod） | `uint8_t motor_id` | 有通道，但只是数字 id，回调内部还得查表找对象 |
| **cyclotron** | `void* ctx` | 直接是对象指针，零查找、零全局 |

wheel 同构 = "函数指针 + 通道参数"形态；`motor_id` 是 ctx 的窄化特例。

## 三、ctx 解决的 5 个问题

1. **每轴手写适配器样板**（D5 原文痛点）：一套实现 + N 个 ctx 服务 N 个电机
2. **全局变量耦合**：回调变纯函数（输入 ctx，输出结果），不碰全局
3. **多实例可测**：PC 测试构造多个假对象当 ctx，实例互不干扰
4. **与 C++ 对象模型对齐**：G431 阶段电机对象本身当 ctx，一行适配
5. **可空**：单电机可传 `nullptr`，不强制

## 四、用法示例

```cpp
// PC 测试：一个实现服务两个实例
struct FakeEnc { float pos; };
float fake_get_angle(void* ctx) { return static_cast<FakeEnc*>(ctx)->pos; }
hal::Hardware hw_a{&a, fake_get_angle, ...};   // ctx 指向 a
hal::Hardware hw_b{&b, fake_get_angle, ...};   // 同一函数，ctx 指向 b
```

```cpp
// G431：电机对象直接当 ctx
float motor_get_angle(void* ctx) {
    return static_cast<Motor*>(ctx)->encoder_.read_angle();
}
```

## 五、为什么不用虚接口 / std::function（D5 排除理由）

- **虚接口**：能解决同样问题，但要求继承 + 虚表，结构重；函数指针 + ctx 更轻，固件骨架掺 C 代码也能用
- **std::function**：可能堆分配，实时中断上下文不允许；裸函数指针 + ctx 零开销（一个寄存器传参）

## 六、落地点

- hal.hpp 的 `struct Hardware { void* ctx; GetAngleFn get_angle; SetPwmFn set_pwm; EnableFn enable; GetCurrentFn get_current; }`（GetCurrentFn v1 恒 nullptr）
- 对比 legacy：`foc_hardware_t` 五个回调全部无参（`float (*get_angle_cb)(void)`），且带 `delay_ms_cb`（D3 非阻塞化后已删）
