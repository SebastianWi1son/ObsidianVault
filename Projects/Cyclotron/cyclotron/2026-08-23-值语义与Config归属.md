# 值语义与 Config 归属（algo 工具类放哪）

日期：2026-08-23
主题：algo 工具类（LPF/Ramp/SmoothPlanner/PID/Deadzone）在 `foc::Config` 与持有者类之间的归属判断

## 核心规则（一句话）

> **有状态 → 参数进 Config + 实例进持有者；无状态（值语义）→ 值对象直接进 Config。**

## 判断标准（三条判据）

带方法的类能否进 Config，问三个问题：

1. 方法是否 const？（不修改内部状态）
2. 是否值语义？（可拷贝、无身份）
3. 是否不持有资源？（无堆/所有权）

全"是" → 值对象，可进 Config；任一"否" → 实例必须由持有者创建，Config 只存参数。

`calc() const` 是编译器帮你执行的"无状态审计"。

## 现有布局对照

| 工具 | 状态 | 参数在 Config | 实例在 |
|---|---|---|---|
| PID | 有（积分/记忆） | `algo::PIDConfig` | FOC 成员 `vel_pid_/pos_pid_` |
| SmoothPlanner | 有（Ramp+双LPF） | `float traj_vmax_/traj_tf_` | FOC 成员 `planner_` |
| LPF | 有（滤波值） | `float vel_lpf_tf_` | Tracker 成员 `vel_lpf_` |
| Deadzone | 无（纯映射） | `algo::Deadzone`（值对象） | 无 |
| PIDConfig | 无 | `algo::PIDConfig`（值对象） | 无 |

Deadzone 与 PIDConfig 同构（值对象进 Config），与 SmoothPlanner 不同构是有原因的：**SmoothPlanner 的 calc 改写内部状态，若值对象进 Config，Config 从"纯配置"变"运行态对象"，拷贝/复用语义崩坏**——有状态 → 必须实例化在运行时拥有者，这是硬约束。

## 心智模型

- "实体"（有身份：拷贝意义模糊/持资源/非 const 方法）vs "值"（可拷贝等价、const 方法、无资源）——**有方法 ≠ 实体**
- C 遗留直觉"struct = 纯字段"不适用于 C++：`std::string`（60+ 方法 + 持堆内存）、`std::chrono::milliseconds`、`std::filesystem::path` 都常见于 Config/Options
- **Config 的契约 = 值语义 + 可复制，不是纯 POD**
- 命名提示：动词+名词（SmoothPlanner/PID）暗示有状态操作；纯映射类（Deadzone）名字像"活物"只是习惯问题，可考虑 Map/Spec 类命名（可选）

## 配套

- foc::Config 内 `algo::Deadzone deadzone_`（{range, soft}，range=0 → 直通，0=disabled 语义与 LPF/Ramp 一致）
- 测试锚点：死区直通/缩放/边界/负对称 6 用例（test_foc）
